# Claude 명령어: Component

특정 프레임워크에 종속되지 않고, 프로젝트에서 이미 사용 중인 UI 프레임워크와 스타일링 방식, 폴더 구조를 감지하여 그에 맞는 컴포넌트를 생성하는 도구입니다.

## 사용법

```
/component [컴포넌트명]                # 새 컴포넌트 생성
/component [컴포넌트명] --with-test    # 컴포넌트 + 테스트 파일 함께 생성
/component [컴포넌트명] --with-story   # 컴포넌트 + 스토리북 파일 함께 생성
```

## 프로세스

### 1. 프로젝트 컨벤션 감지

- 기존 컴포넌트 파일을 확인하여 사용 중인 프레임워크 파악 (React, Vue, Svelte, Angular 등)
- 스타일링 방식 확인 (CSS Modules, Tailwind, styled-components, Sass, 인라인 스타일 등)
- 폴더 구조 패턴 확인 (컴포넌트별 폴더 vs 단일 파일, `index` 배럴 파일 사용 여부)
- 네이밍 컨벤션 확인 (PascalCase, kebab-case 등)
- 타입 시스템 사용 여부 확인 (TypeScript, PropTypes, JSDoc 등)

### 2. 컴포넌트 요구사항 파악

- 컴포넌트명과 역할(설명)을 기반으로 필요한 props 추론
- 사용자가 명시한 props/상태/이벤트 핸들러가 있다면 그대로 반영
- 재사용 가능성을 고려하여 과도하게 구체적인 하드코딩 지양

### 3. 컴포넌트 코드 작성

- 감지된 프레임워크 문법과 스타일링 방식으로 작성
- 감지된 타입 시스템에 맞춰 props 타입 정의
- 접근성(a11y) 기본 속성 포함 (semantic 태그, aria 속성, 키보드 접근성 등)
- 조건부 렌더링, 로딩/에러 상태 등 필요한 경우 기본 처리 포함

### 4. 부가 파일 생성 (옵션 지정 시)

- `--with-test`: 감지된 테스트 프레임워크로 기본 렌더링/인터랙션 테스트 작성
- `--with-story`: 감지된 스토리북 컨벤션에 맞춰 기본 스토리 작성

### 5. 결과 요약 제공

## 출력 형식

```
## 🔍 감지된 프로젝트 컨벤션
- 프레임워크: [예: React, Vue 등]
- 스타일링: [예: Tailwind, CSS Modules 등]
- 폴더 구조: [예: components/Button/index.tsx]
- 타입 시스템: [예: TypeScript]

## 🧩 생성된 컴포넌트
[생성된 파일 경로 및 전체 코드]

## 📄 생성된 부가 파일 (옵션 지정 시)
[테스트/스토리 파일 경로 및 코드]

## ⚠️ 확인이 필요한 사항
- [props 추론 시 불확실했던 부분, 추가 구현이 필요한 로직 등]
```

## 규칙

- 프로젝트에 이미 있는 패턴을 최우선으로 따르고, 감지되지 않을 경우에만 해당 프레임워크의 일반적인 관례 사용
- 하나의 컴포넌트는 하나의 책임만 가지도록 설계 (필요시 하위 컴포넌트 분리 제안)
- 불필요한 전역 상태 사용 지양, props/로컬 상태로 해결 가능한 범위 우선 고려
- 스타일은 하드코딩된 값보다 프로젝트의 디자인 토큰/변수 우선 사용
- 접근성과 반응형을 기본으로 고려하되, 과도한 추측성 기능 추가는 지양
