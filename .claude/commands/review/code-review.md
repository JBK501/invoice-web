# Claude 명령어: Review

변경된 코드를 종합적으로 분석하여 품질, 보안, 성능, 유지보수성 관점에서 리뷰하는 도구입니다.

## 사용법

\`\`\`
/review # 현재 변경사항(unstaged + staged) 리뷰
/review --staged # 스테이지된 변경사항만 리뷰
/review [파일 경로] # 특정 파일 리뷰
\`\`\`

## 프로세스

1. `git diff` / `git status`로 변경된 파일 목록 및 변경 내용 확인
2. 변경된 파일들을 하나씩 읽어 전체 컨텍스트 파악 (필요시 관련 파일도 함께 확인)
3. 아래 리뷰 관점에 따라 항목별로 분석
4. 우선순위별로 정리된 리뷰 결과 제공 (수정 필수 / 권장 / 참고)

## 리뷰 관점

### 🐛 정확성 (Correctness)

- 로직 오류, 엣지 케이스 누락 여부
- null/undefined 처리, 예외 처리 누락
- 비동기 처리 오류 (race condition, unhandled promise 등)

### 🔒 보안 (Security)

- 사용자 입력 검증 누락
- XSS, SQL Injection 등 취약점 패턴
- 민감 정보(API 키, 비밀번호 등) 하드코딩 여부
- 인증/인가 로직 누락

### ⚡ 성능 (Performance)

- 불필요한 리렌더링 (React의 경우 의존성 배열, 메모이제이션)
- N+1 쿼리, 불필요한 반복 연산
- 큰 번들 사이즈를 유발하는 import

### 🧹 코드 품질 (Maintainability)

- 네이밍 컨벤션 일관성
- 함수/컴포넌트 책임 분리 여부 (단일 책임 원칙)
- 중복 코드
- 매직 넘버/문자열 사용

### ✅ 테스트 (Testability)

- 테스트 커버리지 여부
- 테스트하기 어려운 구조인지 확인

### 📝 스타일 (Style)

- 프로젝트 기존 컨벤션과의 일치 여부
- 불필요한 주석/console.log 잔존 여부

## 규칙

- 실제 코드 근거 없이 추측성 지적 금지 (파일:라인 명시)
- 사소한 스타일 지적보다 로직/보안/성능 이슈 우선
- 수정 제안 시 가능하면 구체적인 코드 스니펫 제공
- 프로젝트에 린트/테스트 설정이 있다면 해당 규칙 기준으로 판단
