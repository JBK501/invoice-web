# Claude 명령어: Refactor

동작(behavior)은 유지한 채 코드 구조, 가독성, 유지보수성을 개선하는 도구입니다.

## 사용법

/refactor [파일 경로] # 특정 파일 리팩토링
/refactor [파일 경로] --extract # 함수/컴포넌트 분리 위주로 리팩토링
/refactor --duplicates # 중복 코드 탐지 및 통합

## 프로세스

### 1. 현재 코드 분석

- 대상 파일의 책임 범위, 함수/클래스 크기, 중첩 깊이 파악
- 반복되는 로직, 유사한 패턴 탐지
- 네이밍, 매직 넘버/문자열, 불명확한 조건문 파악
- 기존 테스트 존재 여부 확인 (리팩토링 안전망 확보 목적)

### 2. 개선 지점 식별

- 단일 책임 원칙 위반 여부 (하나의 함수/컴포넌트가 너무 많은 일을 하는지)
- 중복 코드 → 공통 함수/모듈로 추출 가능 여부
- 깊은 중첩 → 조기 반환(early return), 가드 클로즈로 단순화 가능 여부
- 불명확한 네이밍 → 의도가 드러나는 이름으로 변경 가능 여부
- 하드코딩된 값 → 상수/설정으로 분리 가능 여부

### 3. 리팩토링 계획 수립

- 변경 범위를 작은 단위로 나눔 (한 번에 너무 많은 변경 지양)
- 각 변경이 기존 동작을 바꾸지 않는지 검토
- 테스트가 있다면 리팩토링 후에도 통과 가능한 형태로 설계
- 테스트가 없다면, 리팩토링 전 최소한의 안전장치(간단 검증 방법) 제안

### 4. 리팩토링 수행

- 계획에 따라 단계적으로 코드 수정
- 각 단계마다 변경 이유를 명시
- 기존 코드와의 diff 형태로 확인 가능하게 제공

### 5. 결과 검증 및 요약

## 규칙

- 기능적 동작을 변경하지 않음 (버그 수정이 필요해 보여도 별도로 언급만 하고 임의로 수정하지 않음)
- 한 번에 너무 많은 파일/책임을 건드리지 않고, 점진적으로 리팩토링
- 테스트가 없는 코드는 리팩토링 전 최소 검증 방법을 함께 제안
- 과도한 추상화(early abstraction)를 지양하고, 실제 중복/필요가 확인된 경우에만 추출
- 프로젝트의 기존 네이밍/스타일 컨벤션을 따름
