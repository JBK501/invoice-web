# Claude 명령어: Debug

에러 메시지, 예상치 못한 동작, 스택 트레이스 등을 근거로 버그의 근본 원인을 추적하고, 검증 가능한 수정안을 제시하는 도구입니다.

## 사용법

```
/debug "[에러 메시지 또는 증상 설명]"     # 증상을 설명하여 원인 분석 시작
/debug [파일 경로]                      # 특정 파일을 중심으로 문제 분석
/debug --trace                          # 스택 트레이스 기반 원인 추적
```

## 프로세스

### 1. 증상 파악

- 사용자가 제공한 에러 메시지, 스택 트레이스, 재현 방법, 기대 동작 vs 실제 동작을 정리
- 정보가 불충분하면 재현 조건(입력값, 환경, 순서 등)을 우선 확인

### 2. 관련 코드 추적

- 에러 메시지/스택 트레이스에 언급된 파일과 라인을 우선 확인
- `Grep`/`Glob`으로 관련 함수, 변수, 호출부를 폭넓게 탐색
- `git log`, `git blame`으로 문제 코드의 변경 이력 확인 (최근 변경이 원인인지 판단)
- 관련된 상태 관리, 데이터 흐름, 외부 의존성(API, DB, 환경변수 등)까지 추적

### 3. 가설 수립 및 검증

- 가능한 원인을 여러 개 가설로 나열
- 각 가설에 대해 코드 근거(파일:라인)로 뒷받침되는지 확인
- 근거가 약한 가설은 배제하고, 가장 유력한 가설부터 검증
- 필요시 재현 시나리오를 코드/로그 흐름으로 시뮬레이션

### 4. 근본 원인 확정

- 표면적 증상이 아닌 근본 원인(root cause) 명시
- 동일한 원인으로 발생할 수 있는 다른 잠재적 버그도 함께 언급

### 5. 수정안 제시

- 최소 침습적(minimal) 수정을 우선 제안
- 부작용(side effect) 가능성이 있다면 명시
- 재발 방지를 위한 테스트 케이스 또는 방어 코드 제안

## 출력 형식

```
## 🔍 증상 요약
[재현 조건, 에러 메시지, 기대 동작 vs 실제 동작]

## 🧭 원인 추적 과정
- [확인한 파일/함수] → [발견 사항]
- ...

## 🎯 근본 원인
[파일:라인 근거와 함께 명확한 원인 설명]

## 🛠️ 수정 방안
[구체적인 코드 변경 제안 (diff 또는 스니펫)]

## 🧪 재발 방지 제안
- [추가 테스트 케이스 또는 방어 로직]

## ⚠️ 주의사항
[수정 시 영향받을 수 있는 다른 부분]
```

## 규칙

- 코드 근거 없이 추측만으로 원인을 단정하지 않음 (파일:라인 명시)
- 정보가 부족해 원인을 특정하기 어려운 경우, 추가로 필요한 정보(로그, 재현 스텝 등)를 먼저 요청
- 증상만 가리는 임시방편(symptom fix)보다 근본 원인 수정을 우선 제안
- 수정 범위는 필요한 만큼만 최소화 (관련 없는 리팩토링 지양)
- 동일 패턴의 잠재적 버그가 다른 곳에도 있는지 간단히 확인
